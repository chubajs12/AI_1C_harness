# CFE: версия, отдача пользователю и `G:\` (Energy / ОЭК_ШСЮ)

Канон для расширения **ОЭК_ШСЮ** (`energy_OEK_SHSYU_vX_Y_Z.cfe`). Для других проектов — тот же принцип SemVer + неизменяемость уже отданного имени файла на диске обмена, если в `docs/paths-releases.md` проекта указан аналог `G:\`.

## Правила

1. **Каждая новая отдача пользователю** и **каждая копия на `G:\`** (корень, только `.cfe`) = **patch +1** в `<Version>` `ext/Configuration.xml`, новый `DumpCfg`, новое имя `energy_OEK_SHSYU_vX_Y_Z.cfe`. Синхронно: `build/OEK_SHSYU/VERSION`, прошлый корневой `.cfe` в `build/.../old/`.
2. **Запрещено** перезаписывать на `G:\` уже существующий файл **того же имени версии** другим содержимым (`Copy-Item -Force` без проверки). История на `G:\` — неизменяемая по имени версии.
3. **Исключение — без новой сборки:** боевая CFE, которую вернул пользователь, **байт-в-байт** совпадает с **последней нашей отданной** CFE (на `G:\`, в `build/OEK_SHSYU/` или в задаче). Тогда только baseline: тег/снимок, сверка `verify_prod_cfe.py` — **без** bump, **без** DumpCfg, **без** копии поверх другого байтового содержимого на `G:\`.
4. Скрипты: `scripts/1c/copy-cfe-release.ps1` (харнес), `projects/energy/scripts/1c/dump-oek-shsyu-cfe.ps1` (`-CopyToG`).

## Сверка перед «готово»

- Имя CFE на диске = версия из `Configuration.xml`.
- Если копировали на `G:\` — файл с **новым** номером версии или пропуск копии при совпадении хеша с уже лежащим.
- См. также `docs/05_Цикл_доработки_расширения.md` (п. 8), `AGENTS.md` п. 1.14.
