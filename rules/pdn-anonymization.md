# ПДн: обезличивание для dev, тестов и MCP

«ПДн» в задачах харнеса — персональные данные в базах и артеfactах, не учетные данные GitHub.

## Цель

Ноль утечек ИНН, телефонов, e-mail, ФИО и адресов из боевых баз в чат агента, логах, фичах Vanessa и отчетах.

## Источник данных для агента

- Рабочая и тестовая база для разработки и MCP — только обезличенная копия (или синтетика).
- Живая боевая — не канал для `execute_code`, дампов в чат и массовых выгрузок без обезличивания.

## Запреты для агента и людей

- Не копировать в чат, `tasks/*/log.md`, фичи и скриншоты реальные ИНН, телефоны, e-mail, паспортные данные, полные ФИО контрагентов и сотрудников.
- Не использовать в примерах коде и запросах данные из боевой «как есть»; заменять на шаблоны (`7700000000`, `+79000000000`, `test@example.local`, «Иванов И. И.»).
- Секреты (пароли, токены) — только в `project.env.local`, не в git и не в переписке.

## Тесты и Vanessa

- Фичи и подготовка данных через MCP 1С — только на обезличенной базе.
- В ожиданиях шагов — синтетические идентификаторы, согласованные с фикстурами подготовки.

## Проверка (методика команды)

- Перед прогоном набора: выборочный запрос/просмотр — нет ли в тестовых данных полей с ПДн боевого образца.
- После задачи с выгрузкой: grep по сырцам/логам на типовые паттерны ИНН (10/12 цифр в строковых литералах) — только в новых/измененных файлах; подозрительное — заменить или эскалировать.
