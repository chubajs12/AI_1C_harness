# OneBridge — запасной вариант доступа к живой базе

**Основной канал — MCP 1С (`03_MCP_1С.md`).** OneBridge описан здесь на случай, когда MCP 1С поставить нельзя: нет IIS
или прав администратора Windows, нет модуля веб-расширения нужной версии платформы, коробка не применяется к
конфигурации (мобильная платформа, старый режим совместимости), пользователь не разрешил расширения в базе. Переключение
скриптов комплекта — `DB_CHANNEL=onebridge` в `config/project.env.local`: `mcp1c.py`, раннер шагов и проверки пойдут через
`scripts/onebridge/ob_client.py`, `designer.ps1` будет останавливать и поднимать OneBridge вместо пула IIS.

Минусы, из-за которых Energy ушел с OneBridge 16.10.2026: это открытый толстый клиент — падает при нехватке памяти
хоста, виснет с закрытым портом, показывает диалоги и окна на консоли пользователя, держит сеанс базы (мешает UpdateDB),
перед прогонами его надо поднимать, убитый процесс оставляет сеанс на кластере до суток.

## 1. Что это

`OneBridge.epf` — внешняя обработка (из дистрибутива MCP, файл `tools/onebridge/OneBridge.epf`), которая, будучи открыта
в толстом клиенте 1С, поднимает HTTP MCP-сервер на заданном порту **внутри сеанса базы**. Через него агент выполняет в
базе код BSL и запросы с правами пользователя сеанса — без Конфигуратора, без внешнего соединения COM, без публикации
на веб-сервере. Компоненты обработки (`MCPHttpTransport`, `ToonConverter`) — только Windows, поэтому OneBridge живет на
хосте, в сеансе пользователя (console), а не в RDP-сессии Vanessa и не в контейнере.

Инструменты (справочник — `09a_OneBridge_инструменты.md`): `execute_code`, `execute_query`, `get_metadata`,
`get_event_log`, `get_object_by_link`, `get_link_of_object`, `find_references_to_object`, `get_access_rights`.

## 2. Запуск и остановка

```powershell
scripts\onebridge\start-onebridge.ps1           # поднять (ждет до 3 минут, пока порт ответит)
scripts\onebridge\start-onebridge.ps1 -Status   # 0 — отвечает
scripts\onebridge\start-onebridge.ps1 -Stop     # остановить только СВОЙ процесс (PID в .onebridge-<проект>-pid)
scripts\onebridge\start-onebridge.ps1 -Force    # перезапуск
```

Строка запуска: `1cv8.exe ENTERPRISE /S"сервер/база" /N"польз" /P"***" /Execute "OneBridge.epf" /C "Port=<порт>"
/RunModeManagedApplication /DisableStartupDialogs`.

- `/C "Port=1440"`, а не голое `1440`: параметр запуска разбирают и OneBridge, и расширение `client_mcp` (если оно есть
  в базе) — как структуру «ключ=значение»; ключ, начинающийся с цифры, ломает разбор.
- Первый запуск на новой базе может показать «Предупреждение безопасности» на EPF — ответить «Да» в окне 1С (или снять
  у пользователя «Защиту от опасных действий» — `tests`/справка в `04_Vanessa.md`, п. 3).
- Останавливать только свой PID: на машине одновременно работают OneBridge других баз и проектов (в Energy — 1415, 1416,
  1417, 1420–1429) и клиенты людей. «Убить все 1cv8» — запрещено.
- OneBridge держит сеанс базы: Load/UpdateDB с монопольным доступом его требуют закрыть — `designer.ps1` при
  `DB_CHANNEL=onebridge` останавливает и поднимает его сам. Убитый процесс оставляет сеанс на кластере до суток — `scripts\1c\cluster-sessions.ps1`
  (проверено при сборке комплекта: тестовый запуск OneBridge оставил такой сеанс, он завершен этим способом).
- Пользователь называет OneBridge числом порта («1414») — число может быть неточным; имеется в виду OneBridge этого
  проекта на его порту из параметров.

## 3. Клиент из скриптов — `scripts/onebridge/ob_client.py`

```powershell
python scripts\onebridge\ob_client.py --list
python scripts\onebridge\ob_client.py --code "Результат = Метаданные.Версия;"
python scripts\onebridge\ob_client.py --query "ВЫБРАТЬ ПЕРВЫЕ 5 Т.Ссылка ИЗ Справочник.Валюты КАК Т"
python scripts\onebridge\ob_client.py tests\smoke\bsl\env_check.bsl
python scripts\onebridge\ob_client.py --tool get_event_log '{"levels":["Error"],"limit":20}'
```

Скрипты комплекта сами `ob_client.py` не импортируют: они вызывают `scripts/mcp1c/mcp1c.py`, который при
`DB_CHANNEL=onebridge` передает вызов сюда (порт — `ONEBRIDGE_PORT`).

В коде Python: `from ob_client import run_code, run_file, run_query`. Протокол — MCP streamable HTTP: `initialize` →
`notifications/initialized` → `tools/call`; ответ — SSE (`data:`), JSON может быть разбит на несколько строк.

### Правила для кода `execute_code`

- Код выполняется оператором `Выполнить()` как блок операторов: **нельзя** объявлять `Процедура/Функция`, нельзя
  `Возврат`. Результат — присвоить переменной `Результат` (структуры, массивы, примитивы → JSON).
- Шаблон ответа скриптов проверок: `Результат = Новый Структура("ok, ...", ...)`; раннер считает шаг пройденным, если
  `ok = Истина`. Ошибки — массивом строк в результате, а не исключением (исключение скрывает остальные факты).
- Нужны права — `УстановитьПривилегированныйРежим(Истина)` в начале.
- **Табличные части и связанные данные читать запросами.** Обращение «через точку» от ссылки берет данные из кэша
  сеанса OneBridge (до ~20 с) — сразу после действия в интерфейсе это давало ложные расхождения.
- Повтор при сетевом отказе (WinError 10054/10055 — нехватка памяти хоста) — только для читающего кода.
- Пароли тестовых пользователей подставлять в текст BSL из параметров перед вызовом и не печатать в вывод.

## 4. Для чего OneBridge в работе

Те же задачи, что у MCP 1С (`03_MCP_1С.md`, п. 8); у OneBridge есть и готовые инструменты журнала, ссылок и прав.

| Задача | Как |
|--------|-----|
| Проверить факт после деплоя (версия расширения, активно ли, безопасный режим) | `tests/smoke/bsl/env_check.bsl` |
| Компиляция текстов запросов новых модулей до загрузки | `scripts/1c/check-query-texts.py <модули.bsl>` |
| Вайп тестовых данных перед полным прогоном | BSL по шаблону `tests/templates/wipe_by_prefix.bsl` (шаг `ob`) |
| Подготовка НСИ/фикстур, которые нельзя завести через UI | BSL-шаг `ob` (документы — НЕ так, только через UI) |
| Проверка данных после шага интерфейса (статусы, движения, ТЧ) | BSL по шаблону `tests/templates/check_template.bsl` (шаг `check`) |
| Тестовый пользователь с ролями через профили БСП | BSL: пользователь в группе доступа, проверка ролей и `ПравоДоступа` |
| Причина «непредвиденной ошибки» клиента | `get_event_log` по пользователю (`_$PerformError$_`) — в отчете Vanessa текста нет |
| Сеансы базы (кто мешает UpdateDB) | `ПолучитьСеансыИнформационнойБазы()` (список); завершение — `scripts\1c\cluster-sessions.ps1` (rac) |
| Права пользователя на объект | `get_access_rights` с `user_name` |

## 5. Чего через OneBridge не делать

- Не создавать и не проводить документы в тестах — только через интерфейс (Vanessa): тест должен проходить тот же путь,
  что пользователь, иначе он проверяет не систему, а скрипт.
- Не менять данные рабочей базы вне задачи и без согласия; вайп — только тестовых данных по префиксу.
- Не включать регламентные задания базы (в Energy они заблокированы на кластере, `scheduled-jobs-deny`) — обработчик
  задания тест вызывает напрямую через OneBridge.
