# Команда на серверах: контур для нескольких разработчиков

Документы `01`…`09` описывают одного разработчика на одной машине. Этот документ — для случая, когда контур
разворачивается на серверах для команды: несколько людей, у каждого свой агент. Основание — курс «Внедрение разработки
с ИИ в командах» (Vibecoding1C.ru, план на 90 дней) и опыт Energy. Методика для людей (роли, метрики, план по неделям)
— отдельный документ «Методика внедрения ИИ-разработки 1С в новой команде»; здесь — что делает агент и в каком порядке.

Пункты с пометкой **[согласие]** меняют общую инфраструктуру: их выполняет владелец инфраструктуры или агент по его
явному «да». Пометка **[владелец]** — только владелец инфраструктуры, агенты разработчиков это не делают.

## 0. Что меняется по сравнению с одной машиной

| Было (одна машина) | Становится (команда) |
|---|---|
| Все сервисы на `127.0.0.1`, адреса в конфигурации MCP клиента | Адреса из реестра MCP (`mcp-registry.template.md`): `MCP_HOST`, `GRAPH_URL`, `MCP1C_URL` в `project.env.local`; в `mcp/*.json` — хост сервера вместо `localhost` |
| Одна учетка Windows (администратор), агент без проверки разрешений | Учетка Windows на человека без прав администратора; хуки-запреты в настройках клиента агента (набор задает владелец правил, в комплекте его пока нет) |
| Один аккаунт Claude (или другого провайдера) | Место или API-ключ на человека; запасной маршрут при блокировке или лимите |
| Живая общая база для людей и агента | Обезличенная тестовая база на человека; эталонная база проекта — только для выгрузки |
| Один служебный пользователь MCP 1С на все | Служебный пользователь MCP 1С на человека; публикация — только тестовые базы, вход по IP зоны 1 |
| Граф и индексатор читают рабочую копию разработчика | Граф и индексатор читают выгрузку эталонной базы по расписанию |
| Правила в git проекта без remote; правки агент делает сам в основной ветке | Репозиторий правил на Git-сервере: защищенная ветка, правки через MR с ревью владельца правил |
| Память агента в профиле пользователя | Правила процесса — в репозитории; в личной памяти только личное |
| Пары Vanessa на порты, выбранные вручную | Диапазон портов на человека в реестре; своя RDP-сессия для пар |
| Сбой MCP замечают по ошибкам в работе | Мониторинг с алертом владельцу и дублеру |

## 1. Зоны и серверы

Три сетевые зоны, переходы — только перечисленные:

- **Зона 1 — рабочие места.** Сервер разработки (Windows, терминальный) или ПК через VPN: агент, каталоги проектов,
  клиент и Конфигуратор 1С, пары Vanessa. Исходящий трафик к провайдеру модели — только через прокси или шлюз компании.
- **Зона 2 — сервисы.** MCP-сервер (Linux, Docker, GPU для эмбеддингов): граф, индексаторы, справка, синтаксис,
  шаблоны, БСП, формы, v8std. Git-сервер. Мониторинг, учет расхода. Агент эксплуатации — если появится.
- **Зона 3 — данные.** Кластер 1С и СУБД: эталонные базы проектов, тестовые базы разработчиков (только
  обезличенные). IIS с MCP 1С.
- Переходы: 1 → 2 (MCP по HTTP, git), 1 → 3 (Конфигуратор, MCP 1С, Vanessa — только тестовые базы), 3 → 2 (выгрузка
  эталона). Боевые базы — вне контура: изменения переносит человек дельтой (`docs/05`, выпуск в боевую).

## 2. Порядок развертывания

1. **[владелец] Сеть и учетки.** Зоны и правила фаервола по п. 1. Учетка Windows на человека, не администратор.
   Место или API-ключ у провайдера модели на человека. Регламент ключей: кто выдает, как называем, отзыв при уходе.
2. **[владелец] Git-сервер.** Репозиторий правил: этот комплект (с набором comol — `docs/08`, этап 2а) + хуки-запреты.
   Шаблон проекта. Защищенная основная ветка, MR с ревью владельца правил. Бэкап репозиториев вне сервера.
3. **[владелец] MCP-сервер.** Один compose для всех общих MCP и графа (образцы — `docs/mcp-servers/`). Версии образов
   закреплены: тег с номером версии или digest, без `latest` и `*-beta`. Тома данных — вне контейнеров. Пароли (Neo4j,
   лицензия графа) — в `.env` рядом с compose, не в самом compose. Порты открыты только для зоны 1. Модель эмбеддингов
   выбрать до первой индексации: ее смена — полная переиндексация. Все записать в реестр MCP.
4. **[владелец] 1С.** Кластер и СУБД. Эталонная база проекта (из хранилища или CF). Тестовые базы разработчиков —
   обезличенные копии; после обезличивания — тест на утечку: запрос через MCP 1С ищет в базе реальные ИНН, телефоны,
   email (реквизиты контрагентов, физлиц, контактная информация); ноль находок — база годится. MCP 1С (`docs/03`): пул на
   проект, служебный пользователь на человека, только тестовые базы. `publish-mcp.ps1` публикует только на `127.0.0.1` —
   для команды владелец добавляет привязку сайта к адресу сервера и ограничение входа по IP зоны 1 (IIS, «Ограничения
   IP-адресов и доменов»); разработчики пишут адрес в `MCP1C_URL`.
5. **[владелец] Выгрузка эталона.** Задача по расписанию: обновить эталонную базу → выгрузить в файлы
   (`scripts\1c\designer.ps1 -Action Dump`) → индексация индексатора проекта и обновление графа. Рабочие копии
   разработчиков в индекс не попадают. Подключение нового проекта к графу — владелец, в объявленное окно (граф недоступен
   всем на время пересоздания сервиса, `docs/08`, этап 3).
6. **[владелец] Vanessa.** Диапазон портов на человека (MCP менеджера, клиент тестирования) — в реестре. Своя
   RDP-сессия для пар. Профили клиентов в VAParams под обоими ключами (`КлиентыТестирования`,
   `ДанныеКлиентовТестирования`, `docs/04`). После прогона — закрыть своих клиентов штатно и завершить свои спящие
   сеансы. `cluster-sessions.ps1` и `mcp-pool.ps1` обращаются к RAS и IIS на своей машине: на сервере 1С их запускает
   владелец (или агент с его учеткой).
7. **Рабочее место (агент разработчика).** Клон шаблона проекта. `config\project.env.local`: `MCP_HOST`, `GRAPH_URL`,
   `MCP1C_URL` — из реестра, свой пользователь базы и MCP 1С, свои порты Vanessa (`VANESSA_MCP_PORT`, `VANESSA_TC_PORT`);
   конфигурация MCP клиента — из `mcp/` с хостом сервера. Секреты — только в файлах вне git и в чат не пишутся.
   `scripts\doctor.ps1` → дымовой тест. Цель — час от выдачи учетки до ответа агента по метаданным через MCP.
8. **[владелец] Мониторинг и бэкапы.** Проверка по расписанию: ответ каждого MCP из реестра, контейнеры в статусе
   `Exited`, публикации MCP 1С, место на дисках, спящие сеансы 1С. Сбой — сообщение владельцу и дублеру; без
   автоперезапуска. Бэкап: Git, тома MCP, конфиги; восстановление проверить один раз до старта команды.
9. **Приемка контура** — все пункты чек-листа п. 4.

## 3. Правила для агента в командном контуре

- Общие сервисы (граф, общие MCP, сайт IIS, кластер, Git-сервер) агент разработчика не пересоздает, не обновляет и
  не останавливает. Не отвечает — стоп, сообщить человеку (владелец получит алерт мониторинга).
- Адреса, порты, имена баз — только из `project.env.local` и реестра; в правила и скрипты их не вписывать.
- Только своя тестовая база, своя учетка MCP 1С, свои порты Vanessa. Чужие пары, сеансы и базы не трогать.
- Изменения правил и комплекта — отдельной веткой и MR с причиной, не прямым коммитом в основную ветку.
- Правило процесса, которое агент хочет запомнить, — предложение в правила проекта (MR), а не только личная память.
- Данные базы в ответах — без ФИО, телефонов, ИНН, адресов: агрегаты или маскирование. Скриншоты с реальными данными
  в чат не отправлять.
- Изменения в боевую — только дельтой через человека, по порядку выпуска в боевую (`docs/05`).

## 4. Чек-лист приемки контура

- [ ] Новый человек за час: учетка → клон шаблона → `doctor.ps1` без FAIL → агент отвечает по метаданным через MCP.
- [ ] Каждый MCP из реестра отвечает из зоны 1; из других сетей — не отвечает.
- [ ] Хук блокирует тестовую запрещенную команду и возвращает причину.
- [ ] Тест на утечку тестовых баз — ноль реальных ИНН, телефонов, email.
- [ ] Публикация MCP 1С не отвечает с адреса вне зоны 1.
- [ ] Расход виден по каждому человеку (кабинет провайдера, шлюз или телеметрия клиента агента).
- [ ] Остановка любого MCP приводит к алерту владельцу и дублеру.
- [ ] Восстановление Git и томов MCP из бэкапа проверено.
- [ ] Две параллельные сессии разных людей прогоняют Vanessa на своих парах без помех.
- [ ] Реестр MCP заполнен: у каждой строки владелец, версия, дата.
