# MCP 1С: живая база через HTTP-сервис расширения

Канал агента в живую базу: выполнить код BSL и запрос, посмотреть метаданные и данные — без Конфигуратора,
без COM, без клиентского процесса 1С.

## 1. Что это

MCP-сервер живет **внутри базы** как HTTP-сервис расширения и опубликован на IIS этой машины:
`http://127.0.0.1:<MCP1C_PORT>/<MCP1C_APP>/hs/mcp`. Каждый вызов выполняется на сервере 1С в сеансе публикации под
пользователем базы (Basic-авторизация, `USER`/`PASS` из `config/project.env.local`).

| Часть | Что это | Правило |
|-------|---------|---------|
| `MCP_Сервер` | расширение-«коробка» [github.com/vladimir-kharin/1c_mcp](https://github.com/vladimir-kharin/1c_mcp) (MIT): HTTP-сервис `mcp_APIBackend`, протокол MCP, инструменты метаданных | **не менять**; обновлять только новой версией upstream |
| `MCP_ВыполнениеКода` | расширение-компонент с инструментами `execute_code`, `execute_query` ([github.com/chubajs12/MCP_VypolnenieKoda](https://github.com/chubajs12/MCP_VypolnenieKoda)) | свои инструменты — отдельными расширениями-компонентами, не правкой коробки |
| `MCP_Установщик_v*.epf` | служебная обработка: пишет оба CFE расширениями **без безопасного режима** | запускается только из `install-mcp.ps1` |

Дистрибутив — `tools/mcp1c/` архива комплекта (`MCP1C_DIST`). Справочник инструментов — `03a_MCP_1С_инструменты.md`.

Сервис работает, пока работают IIS и кластер. Запускать клиентский процесс не нужно. Для UpdateDB останавливается
один пул IIS (п. 5).

## 2. Установка (один раз на базу; изменение базы — только с согласия пользователя)

Предусловия:

- IIS с компонентом «Расширения ISAPI» (`Install-WindowsFeature Web-Server, Web-ISAPI-Ext` на сервере,
  «Компоненты Windows» на рабочей станции) и модуль веб-расширения 1С той же версии, что `PLATFORM`
  (`wsisapi.dll` в каталоге `bin` платформы — компонент установщика «Модули расширения веб-сервера»).
- `USER` базы — с правом «Администрирование» (только он выполняет `execute_code` без безопасного режима; остальным
  пользователям сервер дает безопасный режим, привилегированный режим не включается, файлы запрещены).
- Свободный порт `MCP1C_PORT` на 127.0.0.1 (если сайт `MCP1C_SITE` уже есть — порт его, публикация добавит приложение).
- Консоль PowerShell от администратора Windows (appcmd).

```powershell
scripts\mcp1c\install-mcp.ps1               # расширения -> публикация -> проверка
scripts\mcp1c\install-mcp.ps1 -NoPublish    # только расширения
scripts\mcp1c\publish-mcp.ps1               # только публикация (повторный запуск обновляет)
```

Что делает `install-mcp.ps1`:

1. Пишет файл задания (пути к последним `MCP_Сервер_v*.cfe` и `MCP_ВыполнениеКода_v*.cfe`) и запускает тонкий клиент
   `ENTERPRISE … /Execute MCP_Установщик_v*.epf /C "<задание>"` под `USER`. Обработка проверяет применимость
   (`ПроверитьВозможностьПрименения`, критичная проблема — ничего не записано), ставит `БезопасныйРежим = Ложь`,
   записывает расширения и завершает сеанс; журнал — `%TEMP%\<PROJECT>_mcp_install.json.log` (`ГОТОВО` в конце).
   **Почему не Конфигуратор и не форма «Расширения»:** оба ставят новое расширение в безопасном режиме, а в нем
   `execute_code` не работает с файлами, внешними обработками и привилегированным режимом.
2. `publish-mcp.ps1` (п. 3) и перезапуск пула — сеансы публикации стартуют заново с новыми расширениями.
3. Проверка: `mcp1c.py --list` (4 инструмента) и `execute_code` → «безопасный режим Нет».

Расширения применяются в новых сеансах, UpdateDB для них не нужен. Повторный запуск — обновление (новая версия коробки:
положить CFE в `MCP1C_DIST`, прошлую — в `old/`, запустить снова). В базу мобильной платформы коробка не ставится
(«Назначения использования» — `PlatformApplication`; в Energy — критичная проблема применения, ничего не записано).

## 3. Публикация (`publish-mcp.ps1`)

- **Только 127.0.0.1.** Сайт `MCP1C_SITE` привязан к `http/127.0.0.1:<MCP1C_PORT>:` — из сети сервис недоступен: он
  выполняет произвольный код под пользователем базы. Не публиковать на `*`/внешний адрес, не открывать порт в брандмауэре.
- **Basic-авторизация 1С.** В `default.vrd` нет пользователя: каждый запрос несет `Authorization: Basic …` (`USER:PASS`).
  Пароль — только в `config/project.env.local`; клиенту агента — через `headersHelper` или переменную окружения
  (`mcp/README.md`).
- **Только сервис MCP.** В `default.vrd` — один `mcp_APIBackend` (rootUrl `mcp`); веб-сервисы, OData и остальные
  HTTP-сервисы выключены.
- **Свой пул IIS** у проекта на версию платформы (`1c_mcp_<PROJECT>_<версия>`): модули `wsisapi` разных версий в одном
  процессе не уживаются, а остановка пула перед UpdateDB не задевает публикации других проектов на том же сайте. Простой
  пула отключен (иначе первый вызов после паузы ждет загрузки модуля 1С).
- **Сеансы публикации** — `reuseSessions` из `MCP1C_REUSE_SESSIONS` (п. 7, риск кэша).
- Файловая база (`INFOBASE_FILE`) публикуется строкой `File="…"`; кластер — `Srvr="…";Ref="…"`.

## 4. Клиент из скриптов — `scripts/mcp1c/mcp1c.py`

```powershell
python scripts\mcp1c\mcp1c.py --status
python scripts\mcp1c\mcp1c.py --list
python scripts\mcp1c\mcp1c.py --code "Результат = Метаданные.Версия;"
python scripts\mcp1c\mcp1c.py --query "ВЫБРАТЬ ПЕРВЫЕ 5 Т.Ссылка ИЗ Справочник.Валюты КАК Т"
python scripts\mcp1c\mcp1c.py tests\smoke\bsl\env_check.bsl
python scripts\mcp1c\mcp1c.py --tool get_metadata_structure '{"metaType":"Catalogs","name":"Валюты"}'
```

В коде Python: `from mcp1c import run_code, run_file, run_query, call_tool`. Протокол — JSON-RPC по HTTP без
состояния: `tools/call` можно слать без `initialize`. Ответ `execute_code` — JSON `{"success", "data", "messages"}`,
клиент возвращает `data`; ошибка 1С — `isError` с текстом и строкой кода → `RuntimeError`. Ответ `execute_query` —
`{"success", "data", "count", "returned", "truncated"}`, `limit: 0` — все строки.

Из PowerShell код с кавычками передавать файлом, а не `--code`: PowerShell 5.1 теряет кавычки внутри аргументов
внешней программы. Кириллицу в командной строке Git Bash тоже лучше не передавать — файлом.

## 5. UpdateDB и монопольный доступ

Сеансы публикации держат базу: UpdateDB с ними не пройдет. `designer.ps1 -Action UpdateDB` сам вызывает
`scripts\mcp1c\mcp-pool.ps1 -Stop` (пул стоп, ожидание выхода рабочего процесса, завершение оставшихся сеансов
`HTTPServiceConnection` под `USER` через `rac` — сеанс без соединения кластер держит и после остановки пула) и
`-Start` после. Так же делает `load-helper-extensions.ps1`. Вручную:

```powershell
scripts\mcp1c\mcp-pool.ps1 -Stop     # MCP проекта до -Start отвечает 503
scripts\mcp1c\mcp-pool.ps1 -Start    # первый вызов после старта — 10–20 с (старт сеанса)
scripts\mcp1c\mcp-pool.ps1           # состояние пула
```

`rac` — через RAS на `RAS_PORT`; служба RAS может быть не установлена, тогда скрипт поднимает временный `ras.exe` и
останавливает его. Клиенты Vanessa и людей пул не трогает: их сеансы — `scripts\1c\cluster-sessions.ps1`.

## 6. Правила для кода `execute_code`

- Код выполняется оператором `Выполнить()` как блок операторов: **нельзя** объявлять `Процедура/Функция`, нельзя
  `Возврат`. Результат — присвоить переменной `Результат` (структуры, массивы, таблицы значений, ссылки → JSON).
- Шаблон ответа скриптов проверок: `Результат = Новый Структура("ok, ...", ...)`; раннер считает шаг пройденным, если
  `ok = Истина`. Ошибки — массивом строк в результате, а не исключением (исключение скрывает остальные факты).
- Нужны права — `УстановитьПривилегированныйРежим(Истина)` в начале (работает только без безопасного режима, п. 2).
- **Табличные части и связанные данные читать запросами** (п. 7).
- Повтор при сетевом отказе и 503 (пул остановлен) — только для читающего кода (`run_code(..., retries=3)`); пишущий —
  `retries=1`.
- Пароли тестовых пользователей подставлять в текст BSL из параметров перед вызовом и не печатать в вывод.

## 7. Известный риск: кэш сеанса при `reuseSessions=autouse`

С `autouse` публикация переиспользует сеансы (вызов — доли секунды), но сеанс держит кэш данных до ~20 с. Следствия
(урок Energy): чтение «через точку» от ссылки сразу после действия в интерфейсе дает старые
данные — ложное расхождение в проверке; запись объекта, только что измененного в интерфейсе, падает «несоответствие
версии» (`ПолучитьОбъект()` берет устаревшую версию). Что делать:

1. Проверки читают табличные части и реквизиты **запросами**, не через точку.
2. Перед записью объекта, только что измененного в интерфейсе, — пауза ~25 с.
3. Не помогает — `MCP1C_REUSE_SESSIONS=dontuse` и `publish-mcp.ps1`: новый сеанс на каждый вызов, кэша нет, но каждый
   вызов дольше на старт сеанса (10–20 с на большой конфигурации). Решение — записать в паспорт (`AGENTS.md` п. 0).

## 8. Для чего MCP 1С в работе

| Задача | Как |
|--------|-----|
| Паспорт конфигурации (имя, версия, БСП, режим совместимости) | `tests/smoke/bsl/config_info.bsl` |
| Проверить факт после деплоя (версия расширения, активно ли, безопасный режим) | `tests/smoke/bsl/env_check.bsl` |
| Компиляция текстов запросов новых модулей до загрузки | `scripts/1c/check-query-texts.py <модули.bsl>` |
| Вайп тестовых данных перед полным прогоном | BSL по шаблону `tests/templates/wipe_by_prefix.bsl` (шаг `ob`) |
| Подготовка НСИ/фикстур, которые нельзя завести через UI | BSL-шаг `ob` (документы — НЕ так, только через UI) |
| Проверка данных после шага интерфейса (статусы, движения, ТЧ) | BSL по шаблону `tests/templates/check_template.bsl` (шаг `check`) |
| Тестовый пользователь с ролями через профили БСП | BSL: пользователь в группе доступа, проверка ролей и `ПравоДоступа` |
| Причина «непредвиденной ошибки» клиента | `tests/templates/event_log_errors.bsl` по пользователю тестов (`_$PerformError$_`) — в отчете Vanessa текста нет |
| Сеансы базы (кто мешает UpdateDB) | `ПолучитьСеансыИнформационнойБазы()` (список); завершение — `scripts\1c\cluster-sessions.ps1` (rac) |
| Права пользователя на объект | `ПравоДоступа("<право>", Метаданные.<…>, ПользователиИнформационнойБазы.НайтиПоИмени("<имя>"))` — без привилегированного режима |
| Структура объекта в живой базе (а не в выгрузке) | `get_metadata_structure`, `list_metadata_objects` |

Метаданные для разработки — по-прежнему индексатор кода и граф (`02_MCP.md`): MCP 1С показывает базу «как сейчас», в том
числе объекты, которых еще нет в выгрузке.

## 9. Чего через MCP 1С не делать

- Не создавать и не проводить документы в тестах — только через интерфейс (Vanessa): тест должен проходить тот же путь,
  что пользователь, иначе он проверяет не систему, а скрипт.
- Не менять данные рабочей базы вне задачи и без согласия; вайп — только тестовых данных по префиксу.
- Не включать регламентные задания базы — обработчик задания тест вызывает напрямую через `execute_code`.
- Не менять коробку `MCP_Сервер` и не публиковать сервис на внешний адрес.
