# Первый запуск: от ссылки на базу до первой доработки

Порядок для агента. Каждый этап — статус пользователю. Пункты с пометкой **[согласие]** меняют базу или общую
инфраструктуру машины: перед ними — спросить пользователя и дождаться явного «да».

## Этап 0. Прочитать

`AGENTS.md` целиком, затем `docs/01`…`07` (бегло — `03a`, `04a`, `reference/`; `09` — только если MCP 1С поставить нельзя). Пользователь пишет «МСП» — это MCP.
Документы написаны на опыте проекта Energy (ERP Энергетика, расширение `ОЭК_ШСЮ`); ваша база — другая конфигурация:
процесс и инструменты те же, а объекты, формы, роли, блоки — только из вашей базы.

## Этап 1. Параметры проекта

1. Получить от пользователя (если не дано в стартовом сообщении): база (сервер кластера + имя базы, или путь файловой
   базы, или файл `.cf`/`.dt`, из которого ее поднять), пользователь базы и пароль, расширение (есть / создать),
   префикс, первая задача.
2. Проверить, что база существует и доступна: список баз кластера (`rac infobase summary list`, если запущен RAS) или
   входом в базу установщиком MCP 1С (этап 4).
3. Если дан файл, а не база: **[согласие]** новая база создается пользователем или агентом (`1cv8 CREATEINFOBASE`),
   `.cf` загружается `/LoadCfg <файл>` и затем отдельно `/UpdateDBCfg`; `.dt` — `/RestoreIB <файл>`.
4. Выбрать свободные порты: Vanessa MCP, клиент тестирования, индексатор
   (`Get-NetTCPConnection -State Listen`; на этой машине заняты: Vanessa 9874–9876, 9894; TC 1538, 1597; кластер
   1540–1591, отладка 1550; RAS 1545 (временный); индексаторы 8013, 8041, 8042, 8052; MCP 8002–8004, 8006, 8008, 8011,
   18766; Neo4j 7474/7687; Ollama 11434). MCP 1С: сайт IIS `1c_mcp` на `127.0.0.1:8095` уже
   есть и общий — проекту нужно только свое приложение (`MCP1C_APP` = имя базы) и свой пул; новый порт — только если
   сайта нет. Предложено: Vanessa 9880, TC 1539, индексатор 8061, MCP 1С 8095.
5. Шаблон `config\project.env.example` скопировать в `F:\AI_1C\projects\<имя>\config\project.env.local` и заполнить: харнес — `F:\AI_1C\harness`, сырцы — `F:\AI_1C\projects\<имя>_src`. Карта — `docs\00_Подключить_проект.md`. Паспорт — `AGENTS.md` п. 0.
6. `scripts\doctor.ps1` — что уже есть, чего нет.

## Этап 2. Каталоги, git, выгрузка

1. `<SRC_ROOT>\conf`, `ext`, `build`; локальные репозитории: `<PROJECT_ROOT>` (настройки) и `<SRC_ROOT>` (сырцы;
   `conf/` — в `.gitignore`). `core.autocrlf=false`. Первый коммит настроек — «комплект как получен».
2. Выгрузка: `scripts\1c\designer.ps1 -Action Dump -Target conf` (долго — фоном, статус), затем
   `scripts\1c\designer.ps1 -Action Dump` (расширение).
3. Расширения нет: **[согласие]** — либо пользователь создает в Конфигураторе (имя, префикс, назначение «Дополнение» /
   «Адаптация», режим совместимости как у конфигурации), либо агент: skill `cfe-init` → `designer.ps1 -Action Load` →
   `-Action UpdateDB`. После — Dump расширения, коммит сырцов «исходное состояние», тег `v0.1.0` или версия из базы.

## Этап 2а. Базовые правила 1С — comol/ai_rules_1c

Набор правил, навыков и субагентов comol/ai_rules_1c — в харнесе Energy и соседних проектах с 20.10.2026; проверенная с
комплектом версия — коммит `1a19311` (28.10.2026; до этого `8907bcd`, 19.10.2026). В архив комплекта не входит (у репозитория нет файла лицензии) — ставится
установщиком из репозитория. Без него комплект работает как раньше, только новые объекты метаданных создает пользователь
(`AGENTS.md` п. 1.2).

1. **[согласие]** Клон во временный каталог: `git clone https://github.com/comol/ai_rules_1c <клон>`, `git -C <клон>
   checkout 1a19311` (новую версию — только после проверки на копии проекта). Из корня проекта:
   `& <клон>\install.ps1 init -Source <клон> -Tools <агент> -NonInteractive` (`claude-code`, `codex`, `opencode`,
   `cursor` — по своему клиенту; для Codex установщик пишет команды и в `~/.codex/prompts`).
2. Что делает установщик (проверено на копии комплекта 1.3.0, `-Tools claude-code`): `AGENTS.md` и `CLAUDE.md`
   комплекта переименовывает в `*.bak.md`, их текст переносит в `USER-RULES.md` между метками миграции; кладет свой
   `AGENTS.md` (~11 КБ), `.claude/rules-1c`, субагентов, команды, навыки, `openspec/`, `.dev.env`, `.ai-rules.json`,
   `memory.md`, `LLM-RULES.md` и шаблонный `.mcp.json`.
3. После установки:
   - `USER-RULES.md`: блок из `AGENTS.md` комплекта оставить целиком — это правила комплекта, старший слой (паспорт
     проекта п. 0 теперь здесь); блок из `CLAUDE.md` комплекта (указатель на `AGENTS.md`) удалить. Первой строкой
     раздела — «Правила комплекта ниже старше `AGENTS.md` и `.claude/rules-1c`: набор MCP, скрипты базы и сборки,
     поставка, жесткие ограничения».
   - `.mcp.json` заменить конфигурацией комплекта (`mcp/claude-code.mcp.json` с параметрами проекта): шаблонный каталог
     comol (`1c-code-metadata-mcp`, `1c-code-check-mcp`, `1c-data-mcp`) не брать. Измененный `.mcp.json` установщик при
     `update` не трогает.
   - `.dev.env` — без паролей: `PREFIX`, `EXTENSION_NAME`, `EXTENSION_NAMES`, `NEW_OBJECTS_IN=extension` (доработка в
     расширении), `INFOBASE_KIND` / `INFOBASE_PATH`, `PLATFORM_VERSION`, `NEW_OBJECT_POSITION=byName` (состав по
     алфавиту), `AGENT_MODEL` (модель головного агента), `CAVEMAN=off`, `SUBAGENT_MODEL_ANALYSIS` (без нее ревьюеры
     comol отключены). Инструменты: `TOOL_GRAPH`, `TOOL_DOCS`, `TOOL_SSL`, `TOOL_SYNTAX`, `TOOL_TEMPLATES` = `auto`;
     `TOOL_CODE`, `TOOL_CHECKER`, `TOOL_DATA`, `TOOL_COGNEE`, `TOOL_OPENVIKING`, `TOOL_QA` = `off` (у комплекта свой
     индексатор, MCP 1С вместо `1c-data-mcp`, Vanessa вместо QA MCP). Пароль базы — только `config/project.env.local`.
   - Навыки комплекта (`skills/`) — в `.claude/skills/` (для Claude Code), только те, которых там нет: навыки comol в
     комплекте той же версии `1a19311`, установленные установщиком не заменять.
4. Команды comol, которые не запускаются (у комплекта свои скрипты и формат поставки): `/installtools`, `/installmcp`,
   `/setupmcp`, `/updatemcp`, `/update1cbase`, `/loadfrom1cbase`, `/deploy-and-test`, `/build-release`,
   `/restore-testbase`, навык `db-ops`; поставка — по формату комплекта, не `1c-change-package`.
5. Обновление набора: `/checkupdates` (только чтение) → `install.ps1 update -Tools <агент> -NonInteractive` из свежего
   клона после проверки на копии проекта → `USER-RULES.md` и `.mcp.json` остались вашими. Новая версия — в паспорт и
   строкой в `docs/changelog.md` настроек.

## Этап 4. MCP 1С и паспорт конфигурации

1. **[согласие]** расширения MCP в базу и публикация на IIS (`docs/03_MCP_1С.md`, п. 2–3): в консоли администратора
   `scripts\mcp1c\install-mcp.ps1`. Предусловия — IIS с «Расширения ISAPI», `wsisapi.dll` нужной версии платформы,
   `USER` с правом «Администрирование». Итог — `MCP готов: http://127.0.0.1:<MCP1C_PORT>/<MCP1C_APP>/hs/mcp`,
   execute_code «безопасный режим Нет». Подключить сервер к клиенту агента (`mcp/README.md`, Basic через
   `headersHelper` или переменную окружения), проверить `python scripts\mcp1c\mcp1c.py --status`.
   Поставить нельзя (нет IIS, нет прав, коробка не применяется, пользователь против расширений) — остановиться
   и сказать пользователю. Другого канала в базу в харнесе нет.
2. `python scripts\mcp1c\mcp1c.py tests\smoke\bsl\config_info.bsl` — конфигурация (имя, синоним, версия,
   поставщик), режим совместимости конфигурации и расширений, БСП и ее версия, объем, расширения → паспорт в
   `AGENTS.md`. От этого зависит дальнейшее: есть БСП — `1c-ssl-mcp`, профили и группы доступа, длительные операции
   БСП; нет БСП — права через роли напрямую, механизмы самой конфигурации. Режим совместимости ниже, чем у служебных
   расширений Vanessa, — загрузка `client_mcp`/`VAExtension` может не пройти (этап 5): сообщить пользователю.
