# Подключить проект к харнесу

Этот файл — ответ на «подключи новую базу к линии 1С». Данные ниже актуальные. Папки проектов не создавать и базы не переносить, пока пользователь не сказал «да» на этот проект.

Харнес один. Правка `rules\`, `skills\`, `scripts\`, `tools\`, `mcp\` в `F:\AI_1C\harness` видна всем проектам: свою копию правил и навыков проект не хранит.

## Два корня

| Что | Путь | Чье |
|-----|------|-----|
| Харнес | `F:\AI_1C\harness` | общее: правила, skills, скрипты, каталог MCP, дистрибутивы |
| Проект | `F:\AI_1C\projects\<имя>` | свое: `PROJECT.md`, задачи, `config\project.env.local`, индексы |
| Сырцы | `F:\AI_1C\projects\<имя>_src` | свое: `conf`, `ext`, `build` |

`<имя>_src` — сосед папки проекта, не каталог внутри харнеса. `PROJECT.md` в папке проекта указывает на `..\..\harness`.

В папке проекта **нет** своей копии `AGENTS.md`, каталога `coordination/` и реестра портов. Только указатели в `PROJECT.md` (образец — `F:\AI_1C\projects\energy\PROJECT.md`):

Полный текст протокола шины в репозиторий проекта не копировать.

Шаблон параметров — `config\project.env.example`. Заполненная копия — `F:\AI_1C\projects\<имя>\config\project.env.local`. Скрипты харнеса читают ее через `KIT_ENV_FILE`. Пароль базы только там.

Шаблоны клиента (`mcp\cursor.mcp.json`, `claude-code.mcp.json`, `opencode.json`, `codex.config.toml`) держат оба блока. Общие адреса в них не переписывают под проект. У частных подставляют имя, порт и путь к сырцам из `project.env.local`. Скрипт заголовка MCP 1С — из харнеса: `F:\AI_1C\harness\scripts\mcp1c\mcp1c.py`.

## Что сделать на «подключи базу»

Скaffold (папки, `PROJECT.md`, черновик `project.env.local`, tasks из шаблона):

```powershell
F:\AI_1C\harness\scripts\new-project.ps1 -Name <имя> -WhatIf   # dry-run
F:\AI_1C\harness\scripts\new-project.ps1 -Name <имя>
# нестандартные сырцы (как energy):
F:\AI_1C\harness\scripts\new-project.ps1 -Name energy -SrcRoot F:\AI_1C\projects\energy_ext_src
```

1. Имя проекта латиницей. Папка `F:\AI_1C\projects\<имя>`, сырцы `F:\AI_1C\projects\<имя>_src\conf|ext|build` (или `-SrcRoot`).
2. `PROJECT.md` в папке проекта: правила/skills — `F:\AI_1C\harness`; шина — `coordination/README.md`; MCP — `docs/mcp-in-projects.md` (см. раздел «Cursor Project» выше).
3. `project.env.local` из шаблона: `HARNESS_ROOT` — харнес, `PROJECT_ROOT` и `SRC_ROOT` — пути этого проекта, база, расширение, префикс, свободные порты частных MCP.
4. Общие MCP не поднимать заново. Проверить, что порты из таблицы отвечают.
5. Частные: индексатор на сырцы этого проекта, публикация MCP 1С на эту базу, слой графа — после согласия.
6. Паспорт в ответе пользователю: имя, оба пути, база, какие частные MCP заведены, какие общие уже были живы.
