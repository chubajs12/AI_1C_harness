# Грабли платформы 1С, выгрузки и тестов (найдено на практике)

Сводка фактов, на которые наступили в Energy (платформа 8.3.27, ERP 2.5, БСП). Перед утверждением «платформа так не
умеет» — проверить в `1c-docs-mcp`.

## Выгрузка / загрузка XML

- Load расширения — только Full; Partial дает неполную подгрузку. `/LoadCfg` + `/UpdateDBCfg` в одной команде —
  «Ошибка в параметрах командной строки».
- Имя расширения кириллицей в командной строке — из файла UTF-8 (литерал в `.ps1` без BOM в Windows PowerShell 5.1
  читается как ANSI и портится). Все `.ps1` комплекта — UTF-8 с BOM.
- `ConfigDumpInfo.xml` руками не писать. Заимствование «только модуль» требует явного `PropertyState`. Директива
  перехватчика модуля формы совпадает с `callType` в `Form.xml`. Тег `SafeMode` не дублировать.
- `Configuration.xml`: сохранять переводы строк (CRLF) и BOM как у выгрузки платформы — иначе дерево расходится с
  выгрузкой и diff показывает «все изменено».
- Выгрузка формы списка иногда пишет путь данных без «~», а загрузка такого XML падает «Неверный путь к данным»
  (Energy: `Список.ДлительноНегорящий` в формах `шсю_РегистрацияДефектов`) — при приеме CFE боевой возвращать «~».
- Форма, собранная генератором (form-compile), хранится в другом порядке тегов, чем у платформы: сверять CFE с CFE,
  а не с `ext`.
- Фиктивные UUID встречаются даже в типовой (ERP 2.5.27: `d4e5f6a7-b8c9-0123-def0-123456789abc` у реквизита документа
  `УтверждениеШтатногоРасписания`) — `uuid-check.py` гонять по своему расширению, не по типовой.
- UpdateDB требует монопольного доступа; `-Dynamic+` не всегда помогает. Мешают сеансы публикации MCP 1С (их
  снимает `mcp-pool.ps1 -Stop`, его вызывает `designer.ps1`), клиенты Vanessa, OneBridge и сеансы убитых клиентов: кластер держит их до суток (`hibernate=yes`); сверять с живыми процессами —
  `scripts\1c\cluster-sessions.ps1`.

## Проверки, которые ничего не находят

- syntax-checker и CheckModules **не разбирают тексты запросов**: `КАК Есть` (зарезервированное слово), `УПОРЯДОЧИТЬ ПО`
  по `ПРЕДСТАВЛЕНИЕ(...)` прошли все проверки → `check-query-texts.py` на живой базе. Так же `КАК В` (`В` — оператор
  «В»): поймано проверкой шаблона вайпа комплекта на живой базе («Ожидается имя»).
- Тонкий клиент и Vanessa **не компилируют** ветки `#Если МобильныйКлиент` → CheckModules `-MobileClient`.
- Обращение `Элементы.<Имя>` к удаленному элементу формы проходит сборку, синтаксис и CheckModules — падает в рантайме.
- Ошибка внутри `Попытка ... Исключение` без записи в журнал невидима: при правке такого кода — логировать/возвращать.

## Код BSL

- В модуле формы не называть локальные переменные именами свойств формы (`Окно`, `Заголовок`, `Элементы`) —
  присваивание падает.
- Параметр, переданный в `ОткрытьФорму`, в клиентском коде формы не читается (`Параметры.X` в `ПередЗакрытием` — «Поле
  объекта не обнаружено»): сохранять в реквизит формы в `ПриСозданииНаСервере`.
- Обработчики событий формы нельзя сделать асинхронными (платформа игнорирует `Отказ`), обработчики команд — можно.
- Условное оформление: параметр видимости — `Видимость`; `ВидимостьЭлемента` платформа молча отбрасывает.
- Поле табличной части, переименованное в `удалить_<Имя>`: старые обращения молча не работают внутри `Попытки` (в Energy
  47 таких обращений в тестовых скриптах).
- HTML внутри GeoJSON в поле HTML — `<`, `>`, `&` только escape-последовательностями JSON: документ поля держит данные в
  textarea, сырая разметка ломает разбор.
- Карты и подобные тяжелые HTML: собирать одной функцией на конфигурацию, библиотеки — готовыми макетами/строкой
  Base64, не склейкой тысяч строк в рантайме; никаких CDN.
- Регламентные задания на клиентской базе бывают заблокированы на кластере (`scheduled-jobs-deny`): тест вызывает
  обработчик напрямую.
- Запись «Группы специальных настроек» в корне справочника из кода не проходит — создавать без группы или руками.
- Псевдонимы таблиц в запросе, совпадающие с ключевыми словами (`В`, `Есть`, `Как`…), — «Ожидается имя» только при
  выполнении; ни syntax-checker, ни CheckModules этого не видят — компилировать запросы на живой базе.
- Имя процедуры формы, занятое контекстом мобильной платформы (было: `ПоказатьНаКарте`), CheckModules отвергает только
  на проверке «Мобильный клиент» («Процедура или функция с указанным именем уже определена») — брать уточненные имена.
- БСП `ГрупповоеИзменениеОбъектовКлиент.ИзменитьВыделенные(Элементы.Список)` читает `ТекущиеДанные.Ссылка`: в
  динамическом списке поля может не быть — передавать массив ссылок (ключи `ВыделенныеСтроки`). Список запрещенных
  реквизитов в модуле менеджера (`РеквизитыНеРедактируемыеВГрупповойОбработке`, `ИмяТЧ.*` — вся ТЧ) БСП учитывает, только
  если объект зарегистрирован в `ГрупповоеИзменениеОбъектовПереопределяемый` (для объектов расширения — заимствование).

## Роли и права (БСП)

- Роли «только Создание» без Редактирования платформа не дает: категории Чтение / Редактирование / СозданиеРедактирование.
  Своим ролям не давать `Delete`/`InteractiveDelete*`; в `Rights.xml` — без явных `value=false`.
- Права пользователю — через профили и группы доступа БСП (не прямым назначением ролей): иначе БСП «отличаются роли».
  БСП не назначает роли пользователю без права входа; тестового пользователя создавать через
  `ДополнительныеСвойства.ОписаниеПользователяИБ` с `ВходВПрограммуРазрешен = Истина`.
- Роли в XML выгрузки БСП ссылаются на «Идентификаторы объектов метаданных/расширений» базы, где собран файл (UUID у
  каждой базы свои) — для другой базы перецеливать по ее выгрузке идентификаторов. Файл загрузки — UTF-8 с BOM.
- Переименование роли с тем же UUID профили и пользователи переживают (ключ — UUID).
- Боковое меню мобильного клиента показывает разделы подсистем, на которые есть право просмотра.

## Мобильный клиент

- Шрифт `kind="Absolute" height="0"` — надписи невидимы.
- Кнопки и DOM в поле HTML не работают — только переход по относительной ссылке и разбор `ДанныеСобытия.Href`.
- Строки-карточки таблиц выравниваются по общей сетке колонок всех строк: ширины внутри строки не действуют.
- `ТекущаяДатаСеанса()` в клиентской ветке МК недоступна (ошибка компиляции на телефоне).
- Средства устройства (геопозиция, камера и т.д.) в МК доступны, только если они включены в «Функциональности
  мобильного клиента» основной конфигурации; расширение их не включает. Вызов выключенной (например,
  `СредстваГеопозиционирования`) — ошибка платформы и закрытие сеанса. Проверить список до того, как писать код;
  местоположение на карте можно взять геолокацией документа поля HTML (`navigator.geolocation`).
- Свойство элемента формы (видимость и т.п.), измененное на клиенте МК, сервер не видит: если сервер затем вернет
  его к своему прежнему значению, до клиента изменение не дойдет. Тонкий клиент и Vanessa этого не показывают.
  Переключать видимость в одном месте или после серверного вызова применять ее на клиенте.
- Мобильный клиент держит последнего пользователя записи базы даже после смены учетных данных: другого
  пользователя проверять отдельной записью базы.

## Vanessa

См. таблицы правил и неполадок в `04_Vanessa.md` (п. 6, 7).

- Заголовок окна элемента справочника с показом кода — «Код Наименование (Синоним)»: шаг «открылось окно» по
  наименованию писать шаблоном с `*` в начале (`"*Участок 3 (*"`), а не «Наименование*».
- Фичи и проверки лежат в общем дереве настроек и выполняются против того, что сейчас загружено в базу: правка тестов
  под еще не загруженное поведение ломает прогон соседней сессии на ее сборке. Такие правки держать отдельно (копия,
  ветка) и вносить перед своей загрузкой.
- Проверочный BSL-скрипт MCP 1С / OneBridge (выполнение через `Выполнить`) — без процедур и функций; правку скрипта, который
  нужен идущему прогону, проверять запуском с несуществующим этапом (компиляция целиком, без действий).
- JS-действие в поле HTML, после которого 1С открывает модальный вопрос, из шага-выражения VAExtension запускать через
  `setTimeout`: иначе обработчик 1С срабатывает внутри выражения, вопрос открывается в контексте служебного окна
  расширения («1С:Предприятие»), и шаг «нажимаю Button0» попадает не в вопрос.
- Всплывающие окна Leaflet закрываются с анимацией: сразу после открытия новой карточки старая еще в документе и стоит
  первой — ссылку брать из последней (`querySelectorAll(...)[length - 1]`).

## Окружение агента (Windows)

- Bash-инструмент схлопывает `\\` в `\` даже в heredoc `<<'EOF'`: Python-патчи с путями и regex портятся молча
  (`\1` → 0x01, `\v` → 0x0B). Патчи с обратными слэшами — файлом; после — поиск управляющих символов.
- Docker Desktop: группа в UI = имя compose-проекта; `docker run` без compose — отдельная запись (так и задумано для
  индексатора). Пользователь без группы `docker-users` не видит Docker (permission denied на pipe).
- Docker-контейнер не видит событий изменения файлов на диске Windows (bind mount) — индексатор переиндексировать вручную.
- Процессы искать по командной строке (`Get-CimInstance Win32_Process`), не по номеру сессии и не по имени exe.
- `sed -i` в Git Bash может переписать весь файл с CRLF на LF (две замененные строки — весь файл в `git diff`): файлы
  1С и CRLF-файлы править скриптом (байты, нормализация, запись с CRLF и BOM) и смотреть `git diff --stat`.
