# Разбор видео: кадр в секунду, транскрипт, связка контекста

Метод общий для линии. В папке проекта его не копировать: там только ссылка на этот файл и результат конкретной встречи (`tasks/`, описания задач).

Кадры и транскрипт сами по себе не факты о базе. Имена объектов, реквизитов и поведение конфигурации по-прежнему брать из живого MCP (`AGENTS.md` п. 1). Из видео переносить только то, что видно на кадре или сказано в записи.

## 1. Куда класть

Папка задачи проекта: `F:\AI_1C\projects\<PROJECT>\tasks\YYYY-MM-DD-кратко\`.

| Что | Где | В git |
|-----|-----|-------|
| Кадры `frames\sec_NNNNNN.png` | папка задачи | нет |
| Транскрипт, описание видео, постановки задач | папка задачи, markdown | по правилам репозитория проекта |
| Сырой звук, json распознавания, выгрузка таблицы | папка задачи | нет, если это не текст постановки |
| Этот порядок работы | `docs\17_Разбор_видео.md` харнеса | да |

Тысячи png в харнес и в git проекта не класть. Временные пробы, которые не нужны как результат задачи, — в `temp\` и удалить по окончании (`AGENTS.md` п. 1.13).

## 2. Кадр на каждую секунду

Нужны `ffmpeg` и `ffprobe` в PATH.

1. Длительность и размер кадра: `ffprobe -v error -show_entries format=duration:stream=codec_type,width,height -of json "<видео>"`.
2. Извлечь png с частотой 1 кадр в секунду. Имя файла — номер секунды от начала ролика, шесть цифр:

```text
ffmpeg -y -i "<видео>" -vf fps=1 -start_number 0 "<задача>\frames\sec_%06d.png"
```

`sec_000083.png` — кадр на 83-й секунде (1:23). Первая секунда — `sec_000000.png`. Число файлов сверять с длительностью: для ролика `N` секунд ожидается около `N` кадров (хвост короче секунды может не попасть в последний файл).

Кадр не уменьшать, если с него нужно читать подписи интерфейса. Хром конференции (шапки участников, боковая панель) в кадр входит: это контекст, кто демонстрирует экран.

## 3. Транскрипт

Основной путь — навык `skills\transcribe` (Gemini). Ключ `GEMINI_API_KEY` только в окружении или в `.env` рядом с навыком, не в git и не в чат.

```text
python skills\transcribe\scripts\transcribe.py "<видео>" --output-dir "<задача>\transcript-gemini" --with-summary
```

Для записи, где показывают формы, тот же скрипт с `--analyze-ui`: кроме дословной речи он пишет протокол и детальный разбор экрана. Таймкоды навыка — `[MM:SS]`, точность порядка нескольких секунд. Это не заменяет поминутную сверку с кадром, если от таймкода зависит номер строки задачи.

Запасной путь, если ключа нет и это прямо записано в `log.md` задачи: локальное распознавание уже установленным STT (на этой машине встречался `faster-whisper`), звук заранее снять `ffmpeg` в wav 16 кГц моно. Не ставить новый секрет «из памяти» и не подменять отсутствующий ключ выдуманным текстом.

В обоих путях сохранить сегменты с началом и концом в секундах. Итог для человека — `transcript.md`: у каждого сегмента таймкод и имя ближайшего кадра.

## 4. Привязка сегмента к кадру

Ближайшая секунда — `round(start)` сегмента, не ниже 0 и не выше номера последнего кадра.

```text
кадр = frames\sec_{секунда:06d}.png
```

В `transcript.md` строка сегмента выглядит так:

```text
[00:12:05-00:12:18] кадр frames/sec_000725.png
Текст реплики.
```

Если реплика длинная и за это время экран сменился, в описании видео ставить дополнительный кадр на секунду смены, а не один кадр на всю реплику.

## 5. Описание видео

Файл `video-description.md` на русском. Это не пересказ одной только речи и не каталог всех png.

Для каждого смыслового отрезка (смена демонстрируемого экрана или смена темы):

1. Интервал `MM:SS-MM:SS`.
2. Имя кадра (начало отрезка и, если нужно, кадр середины).
3. Что на экране: окно, заголовок, открытый список или форма, видимые номера и подписи. Только то, что читается на этом кадре.
4. Что говорят в этом интервале, близко к транскрипту, с тем же таймкодом.

Смену экрана искать по кадрам, а не по памяти. Практический прием: сравнить соседние кадры, уменьшенные до мелкой сетки, и пометить секунды, где средняя яркость скакнула. Порог подбирать по ролику. Хром конференции часто стабилен, а меняется центр демонстрации — сравнивать лучше вырезку области демонстрации, иначе прокрутка таблицы тонет в шапке звонка.

Участников и заголовок комнаты брать с кадра, имена с табличек конференции не угадывать по голосу, пока человек сам не назван или не подписан.

## 6. Связка с внешним списком задач

Если к видео приложен лист (Google Sheets и аналоги):

1. CSV цвет заливки не содержит. Для цвета качать xlsx (`export?format=xlsx`) и читать заливку ячеек, не полагаться на csv.
2. Условие отбора применять целиком: номер, человек, цвет. Строку без нужного цвета в выборку не включать; в итоге отдельно перечислить номера, которые совпали по человеку, но цвет не подтвержден, с фактическим цветом (rgb).
3. Светло-красная заливка таблицы и чисто красная — разные rgb. В отчете писать, какой rgb сочтен «красным», и не смешивать с зеленой заливкой.
4. Момент обсуждения — таймкод транскрипта плюс кадр, на котором виден тот же пункт (номер строки, заголовок формы, фраза). Нет ни речи, ни кадра — писать «на записи не найдено», а не притягивать соседний пункт.
5. Переписанная задача: что сделать, как принять, какие вопросы запись оставила открытыми. Текст листа цитировать. Чего на кадре и в речи не было — не добавлять как факт платформы или как уже принятое решение.

## 7. Что сдать

В папке задачи: `brief.md`, `log.md`, `transcript.md`, `video-description.md`, постановка задач отдельным markdown. В `log.md` — откуда видео, длительность, число кадров, чем распознана речь, сколько строк списка попало в выборку и какие номера цвет не подтвердил.

Проект в своих правилах хранит одну ссылку на этот файл, без копии шагов.
