# AI_1C harness

Общие правила доработки 1С в расширении. Версия — `VERSION`. Харнес один на всю линию: правка правил, skills и каталога MCP здесь видна всем проектам.

Проекты лежат отдельно: `F:\AI_1C\projects\<имя>`, сырцы — `F:\AI_1C\projects\<имя>_src`. Подключить новую базу — `docs\00_Подключить_проект.md`.

Одно предложение: факты о базе берутся из живого MCP, правка идет в расширение, поставка — проверенный файл из Конфигуратора.

## Папки

Их десять. Каждая — одна роль. Подробности внутри не читать пачкой.

| Папка | Роль | Когда открывать |
|-------|------|-----------------|
| `coordination` | шина Project-чатов (inbox jsonl). Протокол — `coordination/README.md`. В проект не копировать | сообщение соседнему чату |
| `config` | шаблон параметров; заполненный файл лежит в папке проекта | первый запуск |
| `docs` | как устроены инструменты; один разобранный проект — как пример | когда нужно «как именно» |
| `mcp` | примеры подключения MCP к IDE | когда подключаешь клиент |
| `rules` | библиотека правил по виду работы, не все сразу | когда пишешь код этого вида |
| `scripts` | свои команды: Конфигуратор, база, Vanessa, индексатор | загрузка, проверка, тест |
| `skills` | навыки. Карта — `skills/README.md` | когда делаешь этот вид правки |
| `tasks` | постановка текущей задачи на диске | каждая задача |
| `tests` | дымовой тест и шаблоны фич | после поставки |
| `tools` | бинарники, которые ставят скрипты (Vanessa, MCP 1С) | установка |

В корне пять файлов: `AGENTS.md` (правила на каждый ход), `START_PROMPT.md` (первое сообщение агенту), `CLAUDE.md` (вход для Claude Code), `README.md` (эта карта), `VERSION`.

## Что читать

1. `docs\00_Подключить_проект.md` — куда класть проект и как делятся MCP.
2. `AGENTS.md` — что нельзя нарушать на любом проекте.
3. Нужный файл из `rules\` и нужный навык из `skills\` — по задаче, не каталогом.
4. `docs\08_Первый_запуск.md` — развернуть окружение.
5. `docs\01_Как_я_работаю.md` и `docs\06_Как_ставились_правила.md` — как это выглядело на одном прошлом проекте. Имена объектов оттуда в свою базу не переносить.

Секреты — только в `project.env.local` проекта, не в харнесе.
